# Contain the existing process mock on the selected Mac

Use the existing process runtime's start/inspect/stop interface and detached trusted
worker for the fixed container fixture. Pin `posix` or `container` once in fresh
SQLite configuration and again in each durable process request. An unset selector
infers the stored choice; conflicting choices refuse. A separate runtime platform
would duplicate admission, accounting and recovery without adding a useful contract.

Container requests carry the run owner and database epoch in private host evidence.
Only admitted synthetic context is mounted. The worker rechecks authority under the
SQLite dispatch guard after container preparation. A claimed launch is never retried.
When a worker is lost, the normal adapter inspects the exact owned container and its
immutable receipt; cancellation can then stop that same container. Unknown evidence
keeps the run unsettled. Synthetic fixture accounting is explicit and separate from
Codex token parsing or provider billing.

Current-data backups require settled process runs and idle workers. Preserve staged
input, claims, identities and terminal receipts, and cross-check them against run,
request and artifact evidence without Docker access. Restore remains held; original
absolute paths are provenance, not authority over the original container. Preserve
the original execution epoch across repeated held backup/restore generations.

This directly defines fresh configuration and request files. Incompatible prototype
stores and requests are refused; no conversion is performed. Actual Codex execution,
credentials and a model transport remain separate work under explicit real-test
selection. The Mac container fixture remains synthetic and network-disabled.
